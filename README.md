# MA4ROM

**A Multi-Agent Framework for Relational-to-Ontology Mapping**

[![Python](https://img.shields.io/badge/Python-3.10--3.13-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![PostgreSQL](https://img.shields.io/badge/PostgreSQL-14%2B-4169E1?logo=postgresql&logoColor=white)](https://www.postgresql.org/)
[![Output](https://img.shields.io/badge/Output-R2RML-7C3AED)](https://www.w3.org/TR/r2rml/)

</div>

MA4ROM generates executable R2RML mappings from a relational database and a
target ontology. Four coordinated stages recognize relational mapping
patterns, align classes and datatype properties, recover object-property
relations, and construct the final mapping.

This repository is a compact public release: current source code, 11 complete
RODI-derived inputs, semantic regression tests, and compact evidence for the
paper's final experimental tables. Caches, logs, prompts, checkpoints, candidate files, backups,
failed runs, repair diagnostics, and duplicate outputs are intentionally not
included.

## Important result provenance

The source and result histories have an explicit boundary:

- `ma4rom/` is the post-paper implementation with the latest general semantic,
  budget-safety, and checkpoint-portability corrections available at release
  time.
- `results/paper/` preserves the originally reported **single-run** MA4ROM
  results and clearly labelled compact summaries from the paper.
- The DeepSeek Table 2 and FK-removal artefacts came from frozen paper snapshot
  `36382fe941480958f4186543998fc195f39f4862`; the GPT-4o column has its own
  recorded source fingerprint.
- The packaged result files were not regenerated by the current source tree,
  and no mean/standard-deviation or repeated-run claim is made.

This distinction is deliberate. Diagnostic MapEnum, pilot, continuation,
offline replay, failed, and budget-paused runs were excluded instead of being
mixed into the formal result set. Full details are in
[`results/README.md`](results/README.md).

## Pipeline

1. **Mapping Pattern Recognition** classifies source tables as SE, SR, or SH.
2. **Class and Datatype Property Mapping** ranks ontology candidates and uses
   schema and instance-value context for ambiguous cases and enumerated values.
3. **Object Property Mapping** combines FK/IND evidence, ontology constraints,
   endpoint compatibility, and relation context.
4. **R2RML Generation** emits executable class, datatype-property, and
   object-property mappings.

## Quick start

### 1. Create an environment

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Python 3.10--3.13 is supported; the public snapshot was verified with Python
3.13. PostgreSQL 14+ is required for a full mapping run.

### 2. Configure credentials

```bash
cp .env.example .env
# Edit .env locally. Never commit it.
set -a
source .env
set +a
```

MA4ROM reads the LLM key and PostgreSQL credentials from environment variables.
There is no key or database password in the tracked source.

### 3. Check and load a dataset

```bash
python tools/setup_dataset.py --check
python tools/setup_dataset.py --list
python tools/setup_dataset.py --load cmt_structured --drop-existing
```

The loader prints the exact environment variables needed for scenarios whose
PostgreSQL schema differs from the scenario name.

### 4. Run MA4ROM

```bash
MAMG_CURRENT_DATABASE=cmt_structured python ma4rom/main.py
```

For Mondial, for example:

```bash
MAMG_CURRENT_DATABASE=mondial_rel \
MAMG_DB_SCHEMA=mondial_rdf2sql_standard \
python ma4rom/main.py
```

Running the full pipeline calls a paid external LLM. Review the limits in
`.env.example` before starting. The default release configuration fixes the
model to DeepSeek V4-Flash, disables thinking/fallback, and enforces request and
token budgets. Generated files go to `ma4rom/output/`, which is Git-ignored.
Generated evaluation properties can contain local database credentials; do not
commit that directory.

## Offline verification

These commands do not access a database, network, or LLM:

```bash
pip install -r requirements-dev.txt
PYTHONDONTWRITEBYTECODE=1 pytest -q -p no:cacheprovider
python tools/verify_release.py
```

The release verifier checks the 11 input bundles, F1 index, Turtle syntax,
query-level metric schema, result checksums, symlinks, forbidden cache/output
folders, personal absolute paths, and common API-key patterns.

## Evaluation

The repository packages final mappings, generated ontologies, aggregate scores,
and compact per-query metrics where the frozen evaluator retained them. For a
new end-to-end benchmark evaluation, use the official
[RODI benchmark](https://github.com/chrpin/rodi) and
[Ontop CLI](https://github.com/ontop/ontop/releases) against the generated
mapping in `ma4rom/output/<scenario>/`.

Ontop binaries are intentionally not vendored: this keeps the repository small
and avoids silently shipping an outdated third-party runtime.
